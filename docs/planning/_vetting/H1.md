# Gemini 3.1 Pro critique — `H1`

**Model:** gemini-3.1-pro-preview
**Duration:** 59.1s
**Source axiom:** `Jacobians/RiemannSurface/LineBundle.lean`
**Verdict:** **reject**

---

Here is a rigorous referee critique of the proposed axiom-discharge plan for `H1`:

**1. Route classification**
The proposed route `needs-infra` is **wrong** for discharging this specific axiom. The correct route is `mathlib-now` (or `provable-from-other-axioms` once `LineBundle` provides a sheaf). The plan conflates *defining* the cohomology group with *proving theorems about it*. Mathlib already has derived-functor sheaf cohomology (`Sheaf.H F 1`). No new infrastructure is needed to define the `H1` type and instantiate its module structure. 

**2. Effort 1..10**
The estimate of 9 is accurate for proving Cartan–Serre finiteness, but it is **wildly overestimated (should be 1 or 2)** for discharging the `H1` axiom itself. Discharging this axiom is literally a one-liner mapping to Mathlib's existing API.

**3. Proof recipe**
The proposed recipe has catastrophic logical and type-theoretic flaws:
- **FATAL ERROR (Topology):** Step 2 claims you can *"fix a cover with |ι| triple intersections empty"*. A Riemann surface is a real 2-manifold, meaning its topological covering dimension is 2. You can refine a cover to eliminate 4-fold intersections ($C^3 = 0$), but you **cannot** eliminate 3-fold (triple) intersections. If you did, $C^2$ would be zero, which means $\delta^1 = 0$, implying every 1-cochain is trivially a 1-cocycle. 
- **FATAL ERROR (Type Theory):** Step 3 sets `H1 L := ker δ¹ / im δ⁰ on a fixed Leray cover 𝒰`. This is invalid Lean. Doing this means the Lean type explicitly depends on the term `𝒰`. The axiom signature `H1 L : Type` does not take a cover as an argument. Leray's theorem provides a canonical *isomorphism* between covers, not a definitional equality. Unless you take a colimit over all covers, you do not get a canonical type. 
- **Misunderstanding of Mathlib:** The plan explicitly dismisses Mathlib's `Sheaf.H F 1` because there is no "analytic-sheaf instantiation" and to avoid "the need for an injective resolution." `Sheaf.H` is entirely polymorphic over any abelian category on any site. Because the line bundle provides a sheaf of $\mathbb{C}$-vector spaces, `Sheaf.H` applies out of the box. You do *not* need to construct an injective resolution just to invoke the definition; you only need it to compute values, which is irrelevant for discharging the type axiom.

**4. Textbook citations**
Forster is the correct mathematical reference for the eventual Cartan–Serre finiteness theorem, but is the wrong reference for how to formally define canonical cohomology types in a theorem prover. Mathlib's sheaf cohomology is based on standard derived functor machinery (Grothendieck).

**5. What's missing or wrong**
- **Decoupling definitions from theorems:** You are trying to stuff a massive analytical result (Cartan-Serre) into the discharge plan for a structural definition. 
- **The topological blunder:** Claiming $C^2 = 0$ for a surface cover shows a fundamental misunderstanding of Čech cohomology and covering dimensions. 
- **The type-dependency blunder:** You cannot mask cover-dependency behind a definition without Lean immediately throwing dependent-type errors when you try to relate $H^1$ of two different line bundles (which might require different trivializing covers).

**6. Recommendation**
**Reject.** Throw out the Čech-complex definition of `H1`. Redesign the plan to define `H1 L := (L.sheaf).H 1` using Mathlib's `Mathlib.CategoryTheory.Sites.SheafCohomology.Basic`. This handles the `Type`, `AddCommGroup`, and `Module` instances immediately. Move the entire bounded Čech complex, Leray's theorem, and Cartan-Serre finiteness into a downstream plan for the finiteness *theorem*, making sure to fix the topological error by properly keeping $C^2$ and showing Leray gives an *isomorphism* to `Sheaf.H 1`.

VERDICT: reject — The plan makes a fatal topological error (triple intersections cannot be empty on a 2-manifold), introduces an invalid type dependency by fixing a cover, and pointlessly reinvents definitions when Mathlib's `Sheaf.H` already provides the canonical type.
