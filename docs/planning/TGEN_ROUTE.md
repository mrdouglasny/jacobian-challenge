## What T-GEN is, exactly

`Jacobians/RiemannSurface/H1Composite.lean`:

```
def AnalyticLoopsGenerateH1 (x₀ : X) : Prop :=
  Submodule.span ℤ (Set.range (loopToHomology : AnalyticLoop X x₀ → H1 X x₀)) = ⊤
```

with `H1 X x₀ := Additive (Abelianization (FundamentalGroup X x₀))` and
`loopToHomology γ = Additive.ofMul (Abelianization.of (fromPath [loopToPath γ]))`.

So an analytic loop's H₁ class is **literally the abelianized π₁ class of its
underlying path**. T-GEN is therefore equivalent to a purely group-theoretic
statement about π₁(X, x₀):

> **(P)** the subgroup of `FundamentalGroup X x₀` generated by the classes of
> analytic loops is all of π₁(X, x₀).

Proof of `(P) ⟹ T-GEN` is Mathlib-only abelianization algebra (see
"The keystone bridge" below): the abelianization of a generating set
generates the abelianized group as a group, and a group generating set of an
additive group ℤ-spans it. **This is the one reusable lemma that converts any
π₁-generation result — family-level or general — into T-GEN.** It is proven in
this lane (no axiom, no sorry): `analyticLoopsGenerateH1_of_pi1_closure`.

That reduces T-GEN to **(P)** for each family / for general X. The rest of
this doc scopes (P).

## The route for general X: the slit-sheet / branched-cover π₁ lift

Every compact Riemann surface X is a finite branched cover `π : X → ℙ¹`
(take any non-constant meromorphic function; the witness families come with
an explicit one). Let `B ⊆ ℙ¹` be the branch locus (finite) and
`T = π⁻¹(B)` the ramification points (finite). On the unramified part,
`π : X∖T → ℙ¹∖B` is a genuine (unbranched, finite) covering map.

The program (the #227/#230 "slit-sheet" lift):

1. **Downstairs generation (DONE, #171 / B1 ladder).**
   π₁(ℙ¹∖B) = π₁(ℂ∖B′) (puncture at ∞ moves into B′) is generated by the
   explicit **circle lassos** around the punctures —
   `closure_circleLassos_eq_top` / `normalClosure_isolatingLassos_eq_top`
   (`Jacobians/Topology/{LassoGeneration,IsolatingLasso,CellGeneration}.lean`).
   These lassos are ANALYTIC loops in ℂ∖B′. This is the upper bound that
   `SVK_BLOCKER.md` once flagged as multi-week — it is now closed.

2. **Lift lassos upstairs.** A based loop downstairs lifts to a *path*
   upstairs (covering path-lifting, `Mathlib.Topology.Homotopy.Lifting` /
   `IsCoveringMap.liftPath`); it closes up to a loop after going around
   `≤ deg π` times (the lasso to a power = its image under the monodromy
   permutation's order). The lifted loop is again piecewise-analytic
   (composition of an analytic base arc with the local analytic sections of
   `π`; for the hyperelliptic √-cover this is exactly the
   `SqrtArcData`/`exists_sqrtArcData` construction already in
   `Hyperelliptic/CycleLoops.lean`).

3. **Lifts + ramification loops generate π₁(X).** The standard
   covering-space exact sequence
   `π₁(X∖T) → π₁(ℙ¹∖B)` together with: filling the punctures `T` back in
   (each ramification point is removable — a small punctured disk upstairs
   is simply connected after the puncture is filled, killing the meridian)
   gives π₁(X) as a quotient of (lifts of downstairs loops). Concretely:
   π₁(X) is generated by the lifted lassos. This is the **honest hard part**
   — see the gap ledger.

4. **(P), hence T-GEN.** The generators of π₁(X) are analytic loops, so (P)
   holds, so `analyticLoopsGenerateH1_of_pi1_closure` gives T-GEN.

This is strictly *weaker* than G-C's full `isBasis` claim (spanning, not

## The named final wall (L2), precisely

The one Mathlib-absent fact, stated minimally:

> **L2.** Let `π : E → Y` be a finite covering map of path-connected spaces,
> `Y` with `π₁(Y)` generated by a set `S` of loop classes. Then `π₁(E)` is
> generated by: (a) the closed lifts of powers of elements of `S`, and
> (b) for the *branched* completion `Ê ⊇ E` filling finitely many
> ramification punctures, the meridian relations are trivialized.

Mathlib supplies **more covering API than previously logged**:
`IsCoveringMap.injective_path_homotopic_map` (Hatcher 1.31: `π_*` injective
on π₁), `monodromy_bijective` / `monodromy_trans_apply`, and the lifting
criterion `existsUnique_continuousMap_lifts_of_range_le` (Hatcher 1.33). So
the covering side of L2 — `π_*` injective, fiber = cosets, stabilizer =
`π_*(π₁ E)` — is available. The **two genuinely Mathlib-absent facts** (named
in `CoveringGeneration.lean`) are:

1. **Combinatorial kernel generation.** From a finite generating set of
   `π₁(ℙ¹∖B)` and the degree-2 parity monodromy `φ : π₁ → ℤ/2`, an explicit
   generating set of `ker φ = π_*(π₁(X∖T))`. The index-2 case is elementary
   (no general Reidemeister–Schreier): with transversal `{1, g₁}`, `ker φ` is
   generated by `{g₁²} ∪ {g₁ gᵢ, gᵢ g₁⁻¹}` (even-word induction). The pair
   generators lift to the branch-cut cycles; `g₁²` lifts to the ramification
   meridian.
2. **Branched puncture-filling.** `π₁(X∖T) ↠ π₁(X)`, kernel = normal closure
   of the ramification meridians; the `z ↦ z²` local model sends each meridian
   to `g₁²`, so filling kills exactly the `gᵢ²`, leaving the `2g` branch-cut
   cycles = `π₁`-generators of the hyperelliptic curve.

**Fact (1) is now PROVEN** (`Index2KernelGeneration.lean`,
`closure_schreierSet_eq_ker`): a fully general index-2 Reidemeister–Schreier
theorem — for `φ : G →* Q`, `t` with `φ t ≠ 1` and `φ t * φ t = 1`, and a
generating set `S` of parity-`{0, φ t}` members, the Schreier set (transversal
`{1, t}`) generates `φ.ker`. Standard-3, sorry-free, Mathlib-only. Its
companion `closure_eq_top_of_surjective` transports a generating set across a
surjection.

**Fact (2) is the sole remaining residual**, now isolated as a single named
datum `PunctureFillData S` (`BranchCutCoveringBridge.lean`): the puncture-fill
van Kampen surjection `π₁(X∖T) ↠ π₁(X)` plus the unbranched-covering
identification `π₁(X∖T) ≅ ker φ`. `branchCutGeneratesPi1_of_punctureFill`
proves `BranchCutGeneratesPi1 S` (hence T-GEN, via K0) from any
`PunctureFillData S` — so the hyperelliptic challenge is closed *modulo
constructing one `PunctureFillData`*. That construction is the genuinely
Mathlib-absent topology: SVK for π₁ (free-product-with-amalgamation /
groupoid pushout) is absent in any form (`CategoryTheory/Limits/VanKampen.lean`
is the unrelated categorical-colimit notion), so building the surjection and
the covering identification is multi-session work (`SVK_BLOCKER.md`).
