# Centauro blueprint

A [`leanblueprint`](https://github.com/PatrickMassot/leanblueprint) for the
Jacobian Challenge — the community-standard tool (FLT, PFR, …) for distributing
Lean work. Generated by `leanblueprint new` (canonical config: `blueprint.sty`,
`plastex.cfg`, `latexmkrc`, `web.tex`, `print.tex`, `macros/`), with our
project-specific nodes in `src/content.tex`.

A subproject **is a blue node** here; see
[`../docs/subproject-format.md`](../docs/subproject-format.md) and
[`../docs/centauro.md`](../docs/centauro.md). Node macros: `\lean{Decl}`,
`\leanok`, `\uses{lbl}`, `\notready`, `\discussion{N}`.

## Building locally

```sh
leanblueprint pdf     # → blueprint/print/print.pdf   (xelatex via latexmkrc)
leanblueprint web     # → blueprint/web/  (open index.html; dep_graph_document.html)
```

`leanblueprint` needs `pygraphviz`, which needs the graphviz dev headers:
```sh
brew install graphviz                              # macOS
CFLAGS=-I"$(brew --prefix graphviz)/include" \
LDFLAGS=-L"$(brew --prefix graphviz)/lib" \
  pip install --user pygraphviz leanblueprint
```

## Not yet wired: `checkdecls`

`leanblueprint checkdecls` (verify every `\lean{}` name exists) needs a
`checkdecls` lake exe. The `leanblueprint new` prompt that adds it was **declined**
to keep the v4.30.0 `lakefile.toml`/manifest under manual control. To enable it,
add the `checkdecls` dependency deliberately and confirm the build stays green on
v4.30.0.

## CI

`.github/workflows/blueprint.yml` (canonical, from `leanblueprint new`) uses
`leanprover/lean-action` + `leanprover-community/docgen-action` (`blueprint:true`)
to build + deploy to GitHub Pages. `lint`/`mk_all-check` are relaxed for the
first run; it triggers on push to `main` only (not on this branch).
